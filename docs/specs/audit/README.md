## Dependencies at a glance
- H2 and M4 touch the same file; ship together.
- M1 and M2 address the same user-visible symptom (failed save, then duplicate).
- L4 before H4; H4 with L3.
- M5 and M6 are one backend PR; M10 pagination reuses M5's bounded `limit` pattern.
- M8 and M9 share the user-timezone design.
- M7 and M9 need migrations: review autogenerated Alembic files, run in staging, back up first.
- H1 before any data repair, and before M9.

## CI and core tests
Cross-cutting work that the specs above rely on (not a numbered finding):
- Add `.github/workflows/ci.yml`: backend `pytest`; frontend `npm ci`, `npm run lint`, `npm run build`; `npm audit --omit=dev --audit-level=high`; `pip-audit -r backend/requirements.txt`.
- Backend tests to add first: auth (register, login, `/me`, expired and invalid tokens), cross-user authorization (user A cannot read, update or delete user B's workouts, routines, notifications), workout/routine CRUD, PR and streak logic, the M1 failure path.
- Frontend has no test runner; add Vitest for pure helpers (`features/workout/utils.ts`, conversion helpers from H1, error helper from L9) when convenient.
- Add `ruff` (and optionally `mypy`) configuration for the backend.
